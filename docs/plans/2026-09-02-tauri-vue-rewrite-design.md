# BatchRename 2.0 Tauri + Vue 重写设计

## 背景与决策

当前 Python 版本已经具备目录扫描、普通文本与正则匹配、结果预览、冲突检查、安全执行、操作日志和整批撤回。经过多轮界面演进，`app.py` 同时承担控件构建、主题、响应式布局、后台消息、结果表覆盖层、日志中心和撤回交互，界面逻辑的规模和耦合开始影响维护与运行流畅度。

下一代版本采用 Rust、Tauri 2、Vue 3 和 TypeScript 重建。重写目标不是逐行翻译 Tkinter，而是在保持现有磁盘安全语义和历史日志兼容的前提下，形成清楚的前端、命令边界、应用服务和领域内核。Python 版本已经整体迁入仓库根目录 `Python` 子项目，在 2.0 发布候选版本通过兼容验证前继续保留和维护。

项目仍以 Windows 10/11 为首要平台。正式发行优先提供 NSIS 安装包，同时验证直接运行的便携 EXE；便携形式依赖系统 WebView2，不承诺脱离 Windows WebView2 环境运行。开发过程继续直接提交到 `main`，不创建功能分支，不主动推送远端。

## 产品目标

- 完整覆盖当前 Python 版面向使用者公开的功能。
- 保持 `%LOCALAPPDATA%\BatchRename\operations` 中现有操作档案可读、可检查和可撤回。
- 文件系统任务不阻塞界面线程，扫描、执行和撤回具有连续进度与明确任务状态。
- 结果列表不再依赖每个单元格创建原生覆盖控件；窗口缩放、滚动和主题切换保持流畅。
- 扫描、预览、执行、日志和撤回通过稳定的数据契约连接，不让 Vue 组件直接操作磁盘。
- 为正式发行建立可重复的 Rust、前端、端到端和安装包验证流程。

## 非目标

- 2.0 首版不处理文件内容，不增加跨目录移动、脚本语言或云同步。
- 不在首版同时开发 macOS、Linux 或移动端发行包。
- 不支持多个磁盘修改任务并行执行。
- 不为保留 Python 实现而引入 Sidecar；Python 只作为旧版产品和兼容行为基准。
- 不承诺支持 Python `re` 的全部冷门扩展语法，只保证已经发布的模板与正式列入兼容清单的语法。

## 技术栈

### 前端

- Vue 3、TypeScript 与 Composition API
- Vite
- Vue Router，桌面资源使用 Hash History
- Pinia，集中管理工作流和用户偏好
- Element Plus，采用按需导入
- Vitest、Vue Test Utils 与 Playwright

### 桌面和后端

- Rust stable-msvc
- Tauri 2
- `serde`、`serde_json`：命令数据和旧日志兼容
- `thiserror`：稳定错误分类
- `regex`：默认线性时间正则
- `fancy-regex`：仅在兼容清单要求高级语法时启用
- `uuid`、`time` 或等价的纯 Rust 时间与标识组件
- Rust 标准文件系统 API；目录遍历保持可控层级和不跟随符号链接

开发环境使用满足当前 Vue/Vite 要求的 Node.js LTS。实施开始前本机只有 Node.js 16.20.2 且尚未安装 Rust；环境门禁最终安装 Node.js 24.19.0、npm 11.17.0、Rust 1.98.0 stable-msvc，并确认现有 Visual Studio 2022 C++ 工具链与 WebView2 Runtime 可用。

## 分层架构

### Vue 展示层

Vue 只处理输入、导航、状态展示、列表分页、主题和无磁盘副作用的界面行为。组件不能直接调用通用文件系统插件。所有可能改变磁盘的操作必须经过带业务名称的 Tauri Command。

主要视图：

- `/rename`：选择目录、规则、扫描、预览和确认执行。
- `/history`：操作日志筛选、列表、概要与逐项详情。
- `/undo`：可撤回记录、安全检查、确认撤回和处理进度。
- `/help`：使用说明、版本、免责声明与作者信息。

正则模板、设置、匹配项详情和执行确认使用抽屉或对话框，不作为独立路由。桌面应用使用 Hash History，避免本地资源路径刷新产生路由解析问题。

### Pinia 应用状态

工作流使用显式状态机：

```text
idle → scanning → matched → previewing → previewReady → executing
                                  └───────────────→ failed

historyIdle → loadingHistory → historyReady
undoIdle → checkingUndo → undoReady → undoing
```

状态仓库只保存可序列化 DTO、当前任务标识和分页信息，不保存 Tauri 窗口、DOM 节点或 Rust 对象句柄。输入变化按照现有规则使匹配快照或预览失效；主题切换不能清空业务状态。

### Tauri 命令边界

前端命令按照用途命名：

- `select_directory`
- `start_scan`、`cancel_scan`
- `build_preview`
- `start_execute`
- `query_operations`、`get_operation`
- `check_undo`
- `start_undo`
- `get_preferences`、`save_preferences`

扫描、执行和撤回返回任务标识，并通过 Tauri Channel 发送带任务标识的进度消息。前端忽略已经失效任务的迟到消息。所有 DTO 使用明确的 `camelCase` 序列化规则并生成或校验 TypeScript 类型。

### Rust 领域与服务层

领域层包含名称规则、扫描选项、匹配项、候选项、执行记录、日志模型和撤回检查结果，不依赖 Tauri。服务层负责文件系统遍历、执行顺序、日志原子写入、任务取消和进度发送。Command 只完成参数转换、权限检查、调用服务和错误映射，不包含重命名算法。

## 扫描与性能设计

- 扫描运行在阻塞任务线程池，不占用 Tauri 主线程。
- 目录遍历不跟随符号链接，严格执行全部层级或 1–N 层范围。
- 第一版不盲目并行读取目录，避免机械硬盘随机访问和网络目录竞争；先通过基准决定是否加入有限并发。
- 进度按时间和数量双重节流，不为每个目录项触发一次 WebView 渲染。
- 完整匹配结果保留在 Rust 任务结果中，前端只获取统计与当前页；默认预览仍为 100 条。
- 结果排序保持文件夹优先、同类自然名称排序和相对目录稳定顺序。
- 日志查询先读取概要索引，选中记录后才读取逐项内容，不在每次筛选时反序列化全部历史明细。

性能验收以同一台机器和同一测试目录比较 Python 版与 2.0：

- 输入、主题和普通导航不触发文件系统读取。
- 扫描开始后 250 毫秒内出现忙碌或进度反馈。
- 扫描期间窗口拖动、缩放和取消操作保持可响应。
- 100、1,000 和 10,000 行模拟数据的列表滚动不创建与总行数等量的 DOM 或原生控件。
- 100、1,000 份日志的首页载入使用分页和延迟详情，不随全部项目明细线性膨胀。
- 安装版冷启动和首屏可交互时间在性能基线机器上形成可重复记录，发布候选不得比 Python 版明显退化。

## 正则兼容契约

普通文本替换、扩展名保护和现有 15 条正则模板必须 100% 等价。兼容清单至少覆盖：

- 捕获组、命名捕获组和常见字符类；
- `^`、`$` 与行内标志，例如 `(?i)`；
- Python 风格替换引用 `\1`、`\g<1>` 和 `\g<name>`；
- 全局替换和空替换；
- 无效表达式、无效替换引用的中文错误说明。

默认优先使用保证线性时间的 `regex`。解析发现 look-around 或模式内反向引用时，只有该语法已经进入正式兼容清单才切换 `fancy-regex`，同时施加表达式长度、回溯限制和取消检查。Rust 端实现独立的 Python 风格替换模板解析器，不能把替换字符串直接交给 Rust 引擎后改变用户语义。

Python 版作为行为 Oracle：测试夹具包含表达式、替换内容、输入名称、是否处理扩展名、期望名称或期望错误。Rust 测试读取同一夹具并逐项比对。

## 安全执行

- 根目录本身永不改名。
- 目标存在、批内目标重复、空名称、Windows 非法字符、设备名和尾随空格或点在预览阶段阻止。
- 执行前重新检查来源、类型和目标，不能依赖旧扫描结论。
- 子项目先于父目录执行；仅大小写变化继续使用唯一临时名称。
- 同一进程只允许一个执行或撤回任务修改磁盘。
- 初始操作日志无法建立时不执行第一项改名。
- 每项完成后先更新内存状态，再原子保存档案；保存失败后停止后续项目并进入中断状态。
- 取消只发生在两个原子文件系统动作之间，不在一次重命名中间中断。

前端不获得任意路径读写权限。目录选择使用官方 Dialog 插件，选中的路径只作为参数传给自定义 Rust 命令；Capabilities 仅开放主窗口实际需要的命令、事件和对话框权限。

## 日志兼容与撤回

Rust 版继续使用 `%LOCALAPPDATA%\BatchRename\operations`，保持现有 `schema_version`、字段名称和中文状态枚举。新增字段必须有默认值，不能在读取时原地重写所有旧日志。

兼容验证使用三类夹具：正常完成、部分失败或中断、部分撤回。每类同时验证 Python 写入后 Rust 读取，以及 Rust 写入后 Python 读取。损坏日志继续隔离展示。

撤回继续基于日志中的事实路径，不重新执行当前查找规则。整批预检检查当前来源、恢复目标、项目类型、嵌套目录推导和日志状态；任一风险阻止整批开始。执行采用原顺序逆序、逐项写档、运行中失败停止和仅重试未恢复项目的现有语义。

## 错误模型

Rust 向前端返回稳定错误结构：

```text
code        稳定机器标识
title       中文标题
message     面向使用者的说明
detail      可选技术细节
recoverable 是否可以调整输入或重试
item        可选关联路径和项目标识
```

预期错误不使用崩溃或裸字符串表达。后台任务中的 panic 必须被任务边界转换为中断状态，并尽力保留已经成功的操作记录。界面只展示安全的用户消息，详细诊断写入本地应用日志，不把完整路径发送到网络。

## 测试策略

### Rust

- 领域单元测试：规则、名称校验、排序和路径推导。
- 临时目录集成测试：扫描、冲突、执行、嵌套目录和仅大小写改名。
- 故障注入：日志创建失败、逐项保存失败、来源消失、目标突然出现和撤回中断。
- Golden Tests：Python 与 Rust 规则结果和 JSON 档案往返。

### Vue

- Store 状态机与迟到任务消息测试。
- 表格分页、溢出提示、主题和响应式组件测试。
- 确认按钮只在有效预览或安全撤回检查后启用。
- Tauri API 在组件测试中使用类型化适配器替身，不在组件内部散布全局 Mock。

### 端到端与发布

- Playwright 验证前端完整流程和不同尺寸布局。
- Windows 真实临时目录验证选择、扫描、预览、执行、日志和撤回闭环。
- NSIS 安装、卸载、升级和中文路径验证。
- 便携 EXE 在具备和缺少合适 WebView2 环境时分别验证并提供清楚提示。

## 发布与切换

- `2.0.0-alpha.1`：只读扫描与预览，不允许修改磁盘。
- `2.0.0-alpha.2`：安全执行与操作日志。
- `2.0.0-beta.1`：撤回管理和旧日志兼容。
- `2.0.0-rc.1`：安装包、便携产物、签名和完整性能验收。
- `2.0.0`：满足全部发布门禁后替换默认下载版本。

每个阶段继续保留 Python 版可构建。只有 Rust 行为夹具、旧日志读取、端到端改名与撤回、发布产物冒烟全部通过，根 README 才把下一代版本标记为当前发行版。

## 完成标准

- 当前公开功能矩阵没有缺项，所有差异均有明确产品决策和文档。
- 现有内置正则模板与兼容清单全部通过跨实现夹具。
- Python 操作日志能够在 Rust 版查看、检查和安全撤回。
- 大型扫描和历史列表不阻塞界面，性能基线记录可复现。
- 前端没有通用文件系统写权限，所有磁盘操作都经过 Rust 业务命令。
- Windows 安装包和候选便携 EXE均通过干净环境验证。
- Python 子项目、2.0 工程和各自产物目录相互独立。
- 所有开发提交使用中文说明，不创建功能分支，不主动推送。
