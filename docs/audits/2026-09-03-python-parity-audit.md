# Python 功能对齐与迁移收口审计

## 结论

文件名管理 2.0 已覆盖原 Python 版本面向使用者公开的功能和磁盘安全语义，并在界面结构、任务隔离、结果浏览及日志撤回整合方面形成更完整的产品体验。旧 Python 子项目已完成行为基线使命，可以退出维护；稳定规则夹具、版本 1 日志样本和性能报告继续作为兼容证据保留。

审计前先在未修改状态运行旧项目完整测试，结果为 `194 passed`。Rust 基线为 33 项集成测试全部通过。审计期间新增的差异用例先稳定复现缺口，再完成实现与回归。

## 审计中发现并闭环的差异

1. 撤回底层已经发送进度，前端却丢弃回调。现在由桌面接口、Pinia 状态和模态进度窗口完整承接，并在结束时区分全部成功与部分失败。
2. 结果表固定显示 100 条，且替换规则变化后使用缓存长度覆盖完整匹配数。现在引入独立的完整总数与显示上限，表格裁剪不再污染业务统计。
3. 初始窗口写死为 1360×840，没有执行既定的屏幕比例适配。现在按显示器工作区与缩放比例计算窗口尺寸，并在定位完成后显示。
4. 日志筛选遗漏运行中及撤回中的中间状态，列表也省略跳过和撤回统计。现在筛选与领域枚举一致，摘要信息足以判断批次结果和待恢复数量。
5. 预览、执行和撤回仍以同步命令承载耗时计算或磁盘操作。现在统一进入后台阻塞任务，并确保任务结束或错误时释放互斥状态。
