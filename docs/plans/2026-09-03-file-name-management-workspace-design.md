# 文件名管理工作台重构设计

## 产品目标

产品正式名称调整为“文件名管理”。工作台不仅用于执行批量重命名，也承担选择目录后的名称浏览、规则匹配、安全预览、执行进度、日志和撤回管理。产品介绍自然覆盖“文件名称管理、批量重命名、文件名管理、高效文件名管理、文件名管理工具”等主要使用场景。

## 列表状态

结果区域明确区分三种状态，避免一份 `items` 同时承担不同语义：

1. `目录内容`：选择目录后立即读取根目录第一层的文件夹和文件，按类型及自然名称排序，最多显示前 100 项；递归数量统计独立进行，不阻塞列表出现。
2. `匹配结果`：输入查找内容并执行扫描后，列表切换为扫描范围内符合普通文本或正则规则的项目。
3. `安全预览`：填写替换内容并预览后，列表显示新名称、状态和说明，只有可修改项目允许执行。

查找内容变化只让旧扫描和预览失效，不清空已经显示的根目录内容。扫描设置变化后返回目录浏览状态，避免继续展示过期匹配结果。

## 后端边界

新增非递归根目录读取命令。它只读取第一层项目、跳过符号链接，按文件夹优先和自然名称排序，返回总数以及前 100 项。递归目录统计继续使用现有命令，两者职责独立；前端先等待轻量列表，再异步刷新统计数据。

## 左侧流程与辅助入口

- 左侧宽度从 35% 收缩到约 30%，为结果表格释放空间。
- 查找框尾部增加信息图标，悬浮卡片说明当前是普通文本还是正则模式，并列出当前查找内容、扫描对象、扫描层级和扩展名保护状态。
- 普通文本与正则模式使用不同示例。正则开关迁入正则模板抽屉顶部，模板应用会自动开启正则模式。
- 替换输入框与“预览”按钮保持一行，按钮宽度和上方“选择”“扫描”一致。
- 正则模板和设置形成独立底部工具栏，固定在左栏底部，不参与流程卡片滚动。

## 结果表格

表格增加固定宽度序号列。类型、状态和说明继续使用图标；所在目录列加宽且标题禁止换行，根目录显示“根目录”，子目录保留紧凑图标并在悬浮时显示完整相对路径。原名称与新名称使用弹性列宽，表格和内部滚动区占满结果卡片剩余高度。

## 执行反馈

用户确认执行后打开模态进度窗口，窗口不可点击遮罩关闭、不可按 Esc 关闭、没有关闭按钮。进度条使用真实的逐项回调，显示已处理数量、当前项目和处理结果；遮罩阻止导航和重复操作。执行完成后关闭进度窗口并显示完成结果；失败时解除忙碌状态并保留错误提示。

## 兼容边界

窗口标题、顶部品牌、页面标题和产品介绍改为“文件名管理”。仓库名称、Rust 包名、应用标识以及 `%LOCALAPPDATA%\BatchRename` 数据目录保持不变，避免升级后丢失日志、设置和撤回能力。

## 验证

- Rust 测试验证非递归读取、排序、符号链接和 100 项上限。
- Pinia 测试验证选择目录后的浏览状态、扫描切换和执行进度。
- 组件测试验证正则入口、查找说明、按钮对齐语义、序号与目录列。
- 端到端测试验证品牌、响应式高度、底部工具栏和阻塞式进度窗口结构。
- 完成类型检查、Rust 静态检查、全部测试和 Windows 构建。
