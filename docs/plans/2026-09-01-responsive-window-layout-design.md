# 多分辨率窗口与响应式工作台设计

## 目标

在保留 960×680 最小可操作尺寸的前提下，让应用根据当前显示器的可用工作区、屏幕方向和宽高比选择合理的初始窗口尺寸，并在用户手动缩放时自动调整内部布局。设计参考 ChatGPT App 的固定导航、弹性内容和窄屏侧栏抽屉思路，不复制其品牌或具体控件外观。

## 屏幕分类

以当前显示器可用工作区的宽高比分类：

- 竖屏：`ratio < 1.15`；
- 标准屏：`1.15 <= ratio <= 2.0`，覆盖 4:3、16:10 和 16:9；
- 宽屏：`ratio > 2.0`，覆盖 21:9 和 32:9。

初始显示器优先选择鼠标指针所在显示器；Windows 下使用 `GetCursorPos`、`MonitorFromPoint` 和 `GetMonitorInfoW` 获取工作区，失败或非 Windows 环境回退到 Tk 虚拟桌面。

## 初始窗口尺寸

所有计算使用逻辑像素，最终尺寸始终不小于 960×680，并限制在显示器工作区边界内。若工作区本身小于最小尺寸，仍保留最小尺寸，由操作系统决定可见区域和窗口移动。

### 标准屏

宽度和高度分别取工作区的 50%，再与最小尺寸取较大值：

```text
width  = max(960, round(work_width  * 0.50))
height = max(680, round(work_height * 0.50))
```

典型结果：1920×1080 为 960×680，2560×1440 为 1280×720，3840×2160 为 1920×1080。

### 宽屏

高度取工作区约 68%，宽度取工作区约 46%，同时将窗口内容比例限制在约 1.7:1：

```text
height = max(680, round(work_height * 0.68))
width  = max(960, min(round(work_width * 0.46), round(height * 1.70)))
```

窗口居中显示，两侧自然保留空间，避免结果表和标题区在 21:9 或 32:9 上无限拉宽。

### 竖屏

宽度取工作区约 90%，高度取约 68%，并限制高度不超过宽度的约 1.15 倍：

```text
width  = max(960, round(work_width * 0.90))
height = max(680, min(round(work_height * 0.68), round(width * 1.15)))
```

竖屏初始使用紧凑内部布局，结果区保持主要宽度，工作流通过侧栏抽屉访问。

## 响应式布局模式

布局模式依据主窗口当前客户区宽度实时计算，而不是只在启动时决定：

- 舒展模式：宽度 `>= 1440`，侧栏约 300 像素；
- 标准模式：宽度 `1120–1439`，侧栏约 270 像素；
- 紧凑模式：宽度 `960–1119`，侧栏折叠为约 64 像素导航条。

主窗口 `<Configure>` 事件使用短延时防抖。只有模式或关键尺寸发生变化时才重新布局，避免拖动窗口过程中持续重建控件。所有输入控件和状态对象保持原实例，切换模式不会丢失目录、规则、匹配快照、预览或执行结果。

## 侧栏与抽屉

舒展和标准模式直接显示完整工作流。紧凑模式显示窄导航条，包含品牌标识、工作流入口和模板/设置入口；点击工作流入口后，在主窗口内展开约 300 像素宽的覆盖式抽屉。

抽屉行为与现有浮动工具一致：

- 再次点击入口、点击结果区或按 Esc 关闭；
- 打开工作流抽屉时关闭模板或设置面板；
- 打开模板或设置时关闭工作流抽屉；
- 面板始终限制在主窗口客户区，不创建额外顶层窗口；
- 忙碌状态下仍可关闭抽屉，但不能改变规则或触发新的任务。

## 结果工作区

结果工作区始终获得剩余宽度和全部额外高度。类型、原名称、新名称和状态保持清楚可见；所在目录和说明使用弹性列宽，空间不足时缩短显示并由现有悬浮提示提供全文。舒展模式增加路径、名称和说明的初始宽度，紧凑模式降低它们的最小宽度，但不隐藏安全状态。

统计条保持单行；预览上限继续位于结果标题右侧。高窗口只增加表格可见行数，标题、统计、进度和状态栏不按比例放大。

## 浮动工具与弹窗

正则模板和设置面板根据当前侧栏宽度重新计算横向锚点，并依据自身请求高度贴近主内容底部，始终限制在客户区。窗口模式切换或缩放后，如果面板仍打开，会立即重新定位。

使用说明、关于和结果详情继续使用现有多屏窗口管理器，跟随主窗口所在显示器居中并限制在工作区。

## 状态与异常处理

窗口尺寸计算由纯函数完成，输入为工作区坐标和尺寸，输出为屏幕类别、窗口几何与初始布局模式。无效或极小工作区回退到 960×680。Windows 显示器 API 失败时不得阻止应用启动。

响应式切换只改变容器放置、侧栏宽度和表格列宽，不改变业务规则。扫描、预览和执行期间切换窗口模式不取消后台任务，也不会解除忙碌态锁定。

## 验证矩阵

纯函数测试覆盖：

- 1920×1080 标准屏；
- 2560×1440 标准屏；
- 3840×2160 标准屏；
- 3440×1440 21:9 宽屏；
- 5120×1440 32:9 宽屏；
- 1080×1920 竖屏；
- 小于最小尺寸的异常工作区；
- 带负坐标的副显示器工作区。

Tk 界面测试覆盖舒展、标准、紧凑三种模式，抽屉互斥和关闭方式，缩放时输入与匹配状态保留，浮动工具重新定位，结果列宽策略，以及 100%、150% 和 200% Tk 缩放下的 960×680 最小布局。
