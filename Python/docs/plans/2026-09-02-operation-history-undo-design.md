# 操作日志与撤回管理设计

## 产品目标

批量重命名的每次实际执行都形成可跨程序重启读取的操作档案。使用者可以从“功能”菜单查看历史规则、执行结果和逐项详情，并对仍满足安全条件的成功操作执行整批撤回。日志不仅用于展示，也是撤回判断的事实依据；无法可靠建立日志时，不开始磁盘改名。

版本进入 `1.1.0-beta.2`。README、内置帮助、关于页面和真实界面预览全部以已经可用的日志与撤回能力重新组织，不再保留“开发中”的旧占位描述。

## 数据保存方案

每次操作使用一个独立 JSON 档案，保存在 `%LOCALAPPDATA%\BatchRename\operations`。独立文件比单一 JSONL 更容易原子更新和隔离损坏记录，也比 SQLite 更便于使用者备份、迁移和人工排查，同时不增加打包依赖。

档案包含：

- 格式版本、操作标识、创建与更新时间；
- 根目录、普通文本或正则规则、替换内容、层级、处理对象与扩展名选项；
- 操作总体状态：准备中、执行中、已完成、部分失败、已中断、撤回检查失败、撤回中、已撤回或部分撤回；
- 匹配、可修改、成功、跳过、失败及已撤回数量；
- 每项的原路径、目标路径、类型、执行结果、说明、撤回结果与说明。

新档案先写入同目录临时文件，刷新后再原子替换正式文件。执行开始前必须成功写入“准备中”档案；每个项目完成后同步更新，避免应用异常退出后完全失去已经发生的操作。启动读取时，无法解析或格式不受支持的档案显示为损坏记录，不阻止其他历史记录和主程序使用。

## 执行与中断状态

使用者确认执行后，应用根据当前预览创建操作档案，然后进入后台改名。只有成功改名的项目进入撤回集合；跳过和失败项目仍保留在日志中，用于说明实际发生了什么。

正常结束时，根据逐项结果写入“已完成”或“部分失败”。若档案停留在准备中或执行中，下次启动时标记为“已中断”，已记录成功的项目仍可接受撤回预检。日志目录不可创建、档案无法初次写入或序列化失败时，直接取消本次执行并显示清楚原因。

执行已经发生后若单次日志更新失败，应用停止继续处理，并尽力把当前内存记录再次保存为中断状态；结果详情明确提示日志异常和人工核对要求。

## 撤回模型

撤回采用整批安全预检。对原操作中成功且尚未撤回的记录按执行顺序反向分析，保证先恢复外层文件夹，再恢复其内部文件和子目录，使操作时记录的目标路径重新有效。

预检检查：

- 当前项目是否能够根据后续成功的文件夹改名推导到现有位置；
- 待恢复名称是否被本次撤回之外的文件或文件夹占用；
- 类型与目录关系是否仍与日志一致；
- 日志是否处于可撤回状态，是否存在另一项撤回正在执行。

任何一项风险都会阻止整批撤回，不改变磁盘，并在明细中标出原因。检查通过后再次显示成功项数量、根目录和不可逆提示，由使用者确认。

撤回按原执行记录逆序逐项进行，并在每项后原子更新日志。系统权限、占用或并发变化仍可能导致运行中失败；此时立即停止，不继续处理后续项目，档案标记为“部分撤回”，已恢复与待重试项目分别保存。再次撤回时只检查和处理尚未恢复的成功项。

仅大小写变化继续复用核心中的临时名称策略。撤回不会删除、覆盖或合并任何现有项目。

## 操作管理中心

“功能”菜单启用“撤回管理”和“操作日志”，两者打开同一个操作管理中心，并自动切换到对应页面。管理中心使用现有同显示器窗口管理方式，保持焦点、边框、任务栏归属和可调整尺寸，不在多屏幕之间漂移。

### 撤回管理

- 顶部说明撤回的安全边界和整批预检原则。
- 左侧按时间倒序列出存在成功操作的档案，显示时间、根目录摘要、成功数量和撤回状态。
- 右侧显示规则、执行统计、当前状态和逐项明细。
- “安全检查”只读磁盘并刷新风险结果；“确认撤回”仅在最新检查通过且档案未变化时启用。
- 撤回完成后刷新列表、详情和主窗口结果详情，不自动重新扫描当前目录。

### 操作日志

- 提供关键词查询和状态筛选，关键词覆盖操作标识、根目录、查找内容和替换内容。
- 历史列表显示时间、根目录、规则摘要、成功/跳过/失败及撤回状态。
- 详情显示完整规则、选项、时间、状态和每项原路径、目标路径、执行结果、撤回结果及说明。
- 日志默认永久保留。本版本不提供批量清空或自动过期，避免意外删除撤回依据。

两个页面共享同一份只读历史缓存和详情组件，不复制磁盘读取逻辑。打开窗口、切换页面或完成执行/撤回后重新加载档案；单条损坏记录作为错误项展示。

## 界面与主题

管理中心延续当前中性表面、靛蓝强调色和浅色/深色主题。列表、筛选、统计、警告、进度和最终动作使用现有语义色；主窗口切换主题时，已打开的管理中心同步更新。确认撤回属于高风险动作，使用独立警示层级，不与普通查看按钮混淆。

前一轮浮动工具面板同时完成收尾：去除“工具”标题，面板从入口附近打开，带主题化边框与阴影，标题可在主窗口范围内拖拽。README 新截图同时体现浮层层级和日志管理中心，不保留旧布局残影。
