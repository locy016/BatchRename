# 匹配结果表紧凑呈现设计

## 目标

在不隐藏安全信息的前提下减少“类型、状态、说明”三列对横向空间的占用，把更多可用宽度交给原名称和新名称。所在目录只显示当前根目录之后的相对路径，避免每行重复完整根路径。

## 路径显示

结果表的“所在目录”统一相对当前扫描根目录显示：

- 根目录直属项目显示 `（根目录）`；
- 深层项目显示从根目录之后开始的目录，例如 `合同\2026`；
- 扫描匹配阶段和结果预览阶段使用相同规则；
- 排序、扫描、预览和执行仍使用完整 `Path`，只改变界面文字；
- 路径无法相对根目录计算时回退完整父目录，避免异常数据阻止列表显示。

## 图标列

类型、状态和说明保留真实文字作为表格数据与详情来源，视觉层使用覆盖在可见单元格上的小型 Canvas 图标：

- 文件夹：中性深蓝文件夹轮廓；
- 文件：中性深蓝折角文档轮廓；
- 可修改：绿色圆形和白色勾选；
- 名称未变化：橙色圆形和白色横线；
- 阻止执行：红色警示形状和白色感叹号；
- 说明：蓝色圆形信息图标。

图标同时使用颜色和形状表达含义，避免只依赖颜色。图标由 Tk Canvas 运行时绘制，不依赖系统 Emoji 字体、不增加图片资源，也不扩大 PyInstaller 数据清单。

## 悬浮与点击

鼠标停在类型、状态或说明图标上时，使用现有产品化提示组件显示完整文字。点击状态或说明图标会选中对应结果行，并打开同屏居中的“匹配结果详情”窗口，显示类型、相对目录、原名称、新名称、状态和完整说明。

详情窗口由现有 `ManagedDialogs` 管理焦点、单实例和多显示器定位。点击另一行图标时刷新同一详情窗口的内容，不调用扫描或磁盘操作。类型图标只提供悬浮说明，点击时按普通行选择处理。

## 自适应列宽

类型、状态和说明为固定窄列，原名称、新名称和所在目录分享剩余空间：

- 类型约 44 像素；
- 状态约 48 像素；
- 说明约 44 像素；
- 所在目录约占弹性空间 26%；
- 原名称约占 34%；
- 新名称约占 40%。

每个响应式档位保留不同最小宽度。空间充足时三列按比例扩展；空间不足时先压缩所在目录，再压缩原名称和新名称，但不会隐藏任何安全图标。Treeview 尺寸变化时原地重新计算列宽，不重建行和覆盖组件。

## 覆盖层与状态

新增的图标覆盖层沿用新名称文字覆盖层的可见行复用思路，只为当前可见单元格维护 Canvas。滚动、缩放、选择和数据刷新后重新定位；离开可视区的图标立即隐藏。覆盖层背景会跟随行选中状态，点击图标不会造成表格与详情行不一致。

每次填充匹配或预览数据时，应用保存以 Treeview 行标识为键的只读显示详情。清空或刷新表格时同步重建映射，避免旧行内容残留。

## 验证

自动化测试覆盖：

- 根目录直属和多层目录的相对路径；
- 路径异常时的安全回退；
- 扫描匹配与结果预览使用相同目录口径；
- 紧凑、标准、舒展三档列宽总量与名称列比例；
- 类型、三类状态和说明图标规格；
- 图标悬浮文字、点击选中与详情窗口内容；
- 列表刷新、滚动和缩放后覆盖层不残留；
- 现有新名称强调、横向滚动条、执行逻辑和111项回归测试继续通过。
