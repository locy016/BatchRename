# BatchRename 产品界面精修设计

## 目标

在不改变安全扫描、预览、执行、日志与撤回能力的前提下，重组重命名工作流、结果表格、帮助导航和主题系统，使软件在常见桌面分辨率下具备清晰的信息层级、一致的深浅色表现和可预测的键盘交互。

## 设计原则

- 工作区只保留完成当前任务所需的信息，解释性内容进入设置或帮助页面。
- 相同概念只出现一次；扫描范围和扩展名保护统一由“设置”管理。
- 关键动作支持鼠标与键盘两种路径，回车行为与当前输入阶段一致。
- 结果表优先表达差异，路径等辅助信息按需展开。
- 主题由统一令牌驱动，抽屉、弹窗、下拉菜单等传送到页面根部的浮层也必须使用相同令牌。

## 窗口与工作区

默认窗口为 1360×840，最小窗口为 1180×760。窗口可自由缩放与最大化；主工作区继续采用左侧流程、右侧结果的双栏结构。左侧保持稳定宽度区间，右侧承担剩余空间，避免结果列在启动时过早截断。

左侧标题只显示“重命名流程”，不再展示“完成预览后才会允许执行”一类脱离操作情境的提示。流程调整为：

1. 选择目录。
2. 输入查找内容并扫描。
3. 输入替换内容并生成预览。
4. 确认并执行。

扫描对象、扫描层级和扩展名保护迁移到“设置”抽屉。左下角保留正则模板与设置入口，避免流程区域重复出现高级选项。

## 键盘交互

- 查找输入框按回车触发扫描。
- 替换输入框按回车触发结果预览；扫描尚未完成时不执行。
- 禁用状态与按钮状态保持一致，不通过回车绕过工作流门禁。
- 执行仍需明确点击确认，不提供直接回车执行，避免误操作。

## 结果表与排序

结果顺序在扫描领域层统一确定，预览继续继承扫描顺序：

1. 文件夹在前，文件在后。
2. 同一类型中，根目录项目在前。
3. 子目录按层级、目录自然顺序排列。
4. 同一目录内按原名称自然顺序排列。

“所在目录”列采用渐进披露：根目录显示 `.`；子目录仅显示文件夹图标。鼠标悬浮图标时展示从当前根目录开始计算的完整相对路径。原名称、新名称继续保留自适应宽度和溢出提示。

## 主题系统

主题令牌分为页面背景、分层表面、文字层级、边框、强调色、状态色、阴影和遮罩。所有业务组件只引用令牌，不直接写固定浅色值。

Element Plus 的颜色变量在浅色与深色主题中统一映射，覆盖：

- 输入框、数值框、选择器和复选框。
- 表格表头、行背景、悬浮和边框。
- 抽屉、对话框、消息提示、工具提示和下拉菜单。
- 遮罩层、滚动条、空状态、进度条和按钮状态。

抽屉内部使用明确的分组卡片、标题、说明和稳定间距，避免内容贴边或在深色主题下出现白色块。

## 帮助信息架构

顶部“帮助”改为菜单触发器，不再直接进入混合页面。子菜单包含：

- 使用说明：独立路由 `/help/guide`。
- 关于：独立路由 `/help/about`。

使用说明页面包括快速开始、完整流程、正则模板入口、结果状态解释、键盘操作和安全注意事项。关于页面包括产品定位、当前能力、后续方向、版本信息、数据位置、免责声明和作者联系方式。两个页面使用统一的页面标题、内容卡片和信息分区，避免把两类内容挤在同一页面。

## 状态与异常处理

- 设置变化继续使旧扫描或旧预览失效，并保留现有任务取消机制。
- 回车触发动作时复用现有门禁，不建立第二套执行路径。
- 路径无法计算为相对路径时回退到原路径，并通过工具提示完整展示。
- 深色主题切换立即作用于页面和已经打开的浮层，不要求重新打开。

## 验证范围

- 组件测试：流程精简、设置归位、替换回车预览、帮助子菜单与独立路由。
- 排序测试：类型、根目录、子目录层级、目录与自然名称的组合顺序。
- 展示测试：根目录文本、子目录图标及完整路径工具提示。
- 主题测试：页面、表格、抽屉和浮层均只使用主题令牌，深色变量完整存在。
- 窗口配置测试：默认尺寸与最小尺寸符合设计。
- 完整回归：前端单元测试、端到端测试、Rust 测试、类型检查、严格检查和 Windows 发行构建。
