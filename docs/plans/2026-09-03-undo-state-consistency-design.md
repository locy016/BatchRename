# 撤回状态一致性设计

## 问题

撤回预检当前只有 `safe` 布尔值。存在风险、日志损坏、没有可撤回项目以及已经完成撤回都会得到 `false`，界面因此统一显示为红色错误。撤回实际成功后，空的待撤回列表被错误解释为“不可撤回”。

## 方案

撤回检查结果增加由后端唯一判定的状态：

- `可撤回`：存在待恢复项目且全部通过安全检查。
- `存在风险`：存在待恢复项目，但至少一项被占用、缺失或类型变化。
- `已撤回`：所有成功改名项目均已恢复原名称。
- `不可用`：日志损坏，或这次操作原本就没有成功改名项目。

执行门禁直接判断 `可撤回`，不再依赖会混淆语义的布尔值。前端按状态选择成功、警告或错误表现；完成状态只显示明确的完成反馈，不再显示“待检查 0 项”和空表格。

撤回执行结束后，撤回检查与左侧操作日志都重新读取持久化记录，保证同一页面中的状态同步。

## 验证

- 后端测试覆盖已撤回、存在风险、可撤回和不可用状态。
- 组件测试覆盖已撤回状态的成功反馈与操作按钮隐藏。
- 页面测试覆盖执行结束后同时刷新检查结果和日志列表。
- 完整运行 Rust、Vitest、类型检查、生产构建和端到端测试。
