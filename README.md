“批量重命名”是一款面向 Windows 的中文桌面工具，用来整理一个目录及其多层子目录中的文件夹和文件名称。它把搜索结果、替换后的名称和不能执行的原因放在同一张表里，让批量操作在真正写入磁盘前保持可见、可检查。

当前发行标识为 **1.1.0-beta.1**。软件处于快速开发期，现有重命名流程已经可用；撤回管理和操作日志是紧接着开发的功能，当前只在菜单中保留“开发中”入口，不会被误表述为已经实现。

程序只依赖 Python 标准库运行，可通过 PyInstaller 发布为单文件 EXE。普通文本规则适合日常整理，正则表达式则用于日期、序号、标签和名称片段等结构化场景。

默认窗口以 960×680 打开，适合在常见桌面空间中与资源管理器并排使用；窗口放大或最大化后，新增空间会自动交给匹配结果列表。

## 界面预览

![批量重命名主界面：左侧两阶段流程、完整统计与统一结果表](docs/images/batch-rename-main.png)

主窗口把一次批量重命名整理成左侧的明确顺序：选择目录、选择普通文本或正则规则、输入查找内容并扫描、填写替换内容、生成结果预览、确认执行。右侧只承担匹配统计、统一结果表和处理进度，窗口放大后新增空间会优先交给结果列表。

顶部菜单只放置全局功能：退出、执行结果详情、使用说明和关于。撤回管理与操作日志以禁用的“开发中”项目提示下一阶段方向，不会与左侧流程命令重复。左下角的“正则模板”和“设置”使用主窗口内浮动卡片，二者互斥显示；再次点击、按 `Esc` 或点击结果区即可收起。

结果表按类型、所在目录、原名称、新名称、状态和说明排列。青绿色新名称便于逐项核对；绿色表示可以安全修改，红色表示目标冲突或其他阻止原因。扫描和结果预览都不会写入磁盘，只有继续点击“确认执行”并通过汇总确认后才会真正改名。

## 适合处理的场景

- 把项目名称中的“旧版”统一替换为“新版”。
- 整理相机生成的 `IMG_001`、`IMG_002` 等序号名称。
- 删除批量文件名前的 `[已审核]`、`[归档]` 等标签。
- 将 `2026-08-27` 整理为 `20260827`。
- 清理重复空格、混用的连接符、旧版前缀和副本后缀。
- 将 JPEG、JPG 等扩展名整理为统一写法。
- 在不修改磁盘的情况下，仅查询多层目录里有哪些名称符合条件。

## 功能

### 清楚的匹配结果

扫描以“名称是否符合查找条件”为准，而不是以“替换后是否发生变化”为准。即使查找和替换内容相同，符合条件的项目仍会出现在结果中，并标记为“名称未变化”。这样既可以验证规则，也可以把程序当作目录名称查询工具使用。

文件夹和文件显示在同一张表中，按“类型、所在目录、原名称、新名称、状态、说明”的顺序阅读，默认以文件夹优先、文件其次、同类名称自然顺序排列。新名称使用青绿色单独强调，便于在执行前快速对照。匹配总数、可修改数、名称未变化数和阻止执行数始终在一行分别统计，不会把“没有执行动作”误写成“没有匹配”。

类型和状态列保持紧凑，名称与所在目录自动分享其余宽度。横向滚动条只在确实需要时出现；名称、路径或说明被列宽缩短时，把鼠标停在对应单元格即可查看完整内容。

### 两阶段工作流与自适应界面

“扫描”和“结果预览”承担不同职责。扫描只读取目录并列出名称符合查找条件的文件夹和文件，不要求先填写替换内容；结果预览使用这次匹配快照计算新名称、名称未变化、目标冲突和非法名称等状态，不会再次遍历目录。替换内容改变时只需重新预览，目录、层级、对象类型、查找规则或正则模式改变时才需要重新扫描。

查找框按 Enter 等同于“扫描”，替换框按 Enter 等同于“结果预览”。只有生成预览且存在“可修改”项目后，“确认执行”才会启用。预览默认显示前 100 条，完整统计和最终执行范围不受显示上限影响。

960×680 是完整可操作的默认与最小尺寸，不是固定画布。左侧流程保持紧凑，右侧结果区随窗口放大或最大化自然增加可见行数。输入框、数值框、选择控件、按钮、提示卡、滚动条和进度条使用统一的深蓝与青绿色视觉语言，焦点、悬停、禁用和执行状态都有清晰差异。

### 普通文本与正则表达式

普通模式按原样查找文本，并替换名称里的每一处匹配。替换内容可以留空，表示删除匹配文本。

正则模式支持 Python 正则语法。不了解正则也可以点击左下角“正则模板”：程序内置 6 类 15 条经过真实规则验证的常用模板，先展示用途和处理前后效果，再通过“一键应用此规则”填写查找、替换及必要选项。应用模板不会扫描目录，也不会直接修改文件。

| 用途 | 查找表达式 | 替换内容 | 示例结果 |
| --- | --- | --- | --- |
| 压缩日期 | `(\d{4})-(\d{2})-(\d{2})` | `\1\2\3` | `2026-08-27` → `20260827` |
| 统一日期分隔符 | `(\d{4})[._/](\d{2})[._/](\d{2})` | `\1-\2-\3` | `2026.08.27` → `2026-08-27` |
| 保留图片序号 | `IMG_(\d+)` | `照片_\1` | `IMG_001.jpg` → `照片_001.jpg` |
| 删除方括号标签 | `\[[^\]]+\]` | 留空 | `[已审核]合同.docx` → `合同.docx` |
| 合并连续空格 | `\s{2,}` | 单个空格 | `项目  最终  版本` → `项目 最终 版本` |
| 删除副本后缀 | `[_-](副本\|copy)$` | 留空 | `预算_副本.xlsx` → `预算.xlsx` |
| 交换名称片段 | `(.+)_([A-Z]+)` | `\2_\1` | `project_FINAL.txt` → `FINAL_project.txt` |
| 统一 JPEG 扩展名 | `(?i)\.jpe?g$` | `.jpg` | `照片.JPEG` → `照片.jpg` |

模板按日期时间、编号整理、标签清理、文本清理、片段调整和扩展名分类。涉及扩展名的模板会自动开启“允许修改扩展名”，并在模板详情中提醒核对；其他模板默认继续保护文件扩展名。

### 层级与对象范围

- 默认扫描到最深子目录。
- 可限制为 1–N 层；第 1 层表示根目录中的直接子项。
- 可单独选择文件夹、文件或两者。
- 所选根目录本身不参与匹配和重命名。
- 符号链接不会被跟随，避免扫描越出所选目录。

### 扩展名保护

文件扩展名默认不参与替换。例如查找 `jpg` 时，`照片.jpg` 会作为匹配结果列出，但状态会说明扩展名受到保护，因此不会执行动作。只有在“设置”中明确勾选“允许修改扩展名”后，规则才处理完整文件名。

### 安全执行

- 目标名称已经存在时不覆盖，直接标明冲突原因。
- 多个来源生成同一个目标名称时，相关项目全部停止执行。
- Windows 非法字符、保留设备名、空名称和尾随空格或句点会提前拦截。
- 扫描完成后若文件系统发生变化，执行时再次检查来源和目标。
- 深层项目先处理，父目录最后改名，避免父路径变化导致子项目失效。
- 执行前展示汇总并二次确认；执行中显示当前项目和总体进度。

程序不会覆盖已有名称，也不会自动撤销已完成的操作。重要目录仍建议先备份。

## 开始使用

### 使用单文件程序

运行 `BatchRename.exe` 后：

1. 在左侧选择根目录；根目录本身不会参与改名。
2. 选择普通文本或正则表达式，输入查找内容，点击“扫描”。此时即使尚未填写替换内容，也会列出所有名称匹配项。
3. 如需限制层级、只处理文件夹或文件、允许修改扩展名，点击左下角“设置”；不熟悉正则时可在“正则模板”中选择并一键应用。
4. 填写“替换为”，点击“结果预览”，检查类型、所在目录、原名称、新名称、状态和说明。
5. 确认存在可修改项目后点击“确认执行”，阅读最终汇总并完成二次确认。
6. 等待进度结束；本次处理记录可从顶部“功能 → 结果详情”查看。

“预览上限”默认是 100 条，只控制界面显示的前几条结果，不改变完整匹配统计和最终执行范围。

### 从源码运行

需要 Python 3.11 或更高版本：

```powershell
python main.py
```

运行程序本身不需要安装第三方库。

## 测试与构建

安装开发依赖：

```powershell
python -m pip install -r requirements-dev.txt
```

运行测试：

```powershell
python -m pytest -v
```

构建带应用图标的单文件 EXE：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

构建脚本会先运行完整测试，测试通过后才生成 `dist\BatchRename.exe`。
