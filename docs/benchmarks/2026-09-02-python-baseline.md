# Python 版工作流性能基线

## 测量目的

本基线用于比较同一台机器上 Python 版与 BatchRename 2.0 的名称扫描和结果预览，不用于宣称脱离硬件、磁盘状态和目录结构的绝对性能。测试目录由脚本临时创建，名称均为规则化演示数据；测试只扫描和生成预览，不执行重命名。

## 环境

- 项目基线提交：`14a6814`
- 操作系统：Windows 11 家庭中文版 64 位，10.0.26200
- 处理器：Intel Core Ultra 9 285H，16 核 / 16 逻辑处理器
- 内存：约 31.5 GiB
- Python：3.13.12
- 存储位置：系统临时目录

## 场景

每个场景创建 20 个分类目录，并在分类目录中平均放置指定数量的空文件。全部文件名称包含“项目”，扫描全部层级，普通文本匹配“项目”，预览替换为“客户”。`entries` 包含文件和分类目录，因此比文件数量多 20。

| 文件数量 | 扫描项目总数 | 匹配 | 可修改 | 扫描耗时 | 预览耗时 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1,000 | 1,020 | 1,000 | 1,000 | 15.028 ms | 13.331 ms |
| 10,000 | 10,020 | 10,000 | 10,000 | 71.869 ms | 152.991 ms |
| 100,000 | 100,020 | 100,000 | 100,000 | 869.126 ms | 1,812.990 ms |

## 解读

扫描主要受目录枚举与磁盘缓存影响，当前测试中的增长接近线性。预览在 100,000 个匹配项时达到约 1.8 秒，包含目标路径构造、Windows 名称校验、目标存在检查、批内目标归组和完整结果集合创建。现有界面默认只显示 100 条，但后台仍会为全部匹配项生成候选。

本数据不测量 Tk 界面渲染。当前可感知卡顿还包含结果表覆盖 Label、Canvas 与 Tooltip 的定位和重绘，以及固定 80 毫秒消息轮询。Tauri 对比必须分别记录 Rust 领域处理和首批结果到达前端的时间，不能只比较单一总耗时。

## 复现

从 `Python` 目录执行：

```powershell
python tools/benchmark_workflow.py --entries 1000
python tools/benchmark_workflow.py --entries 10000
python tools/benchmark_workflow.py --entries 100000
```

每次运行都会创建新的临时目录并在结束后清理。创建 100,000 个文件本身可能需要较长时间，不计入输出的扫描和预览耗时。
