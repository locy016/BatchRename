# 批量重命名紧凑自适应界面设计

## 目标

本轮改版让主窗口在 960×680 的默认尺寸下完整可用，并能在最大化或任意放大后把新增空间优先交给匹配结果列表。查找和替换始终保持在同一行，减少卡片、标题和操作区的纵向占用，同时统一改善控件质感与长内容查看体验。

正则功能从少量演示升级为面向非技术使用者的模板库。使用者通过分类、用途和处理前后示例理解规则，点击一次即可把查找表达式、替换内容及必要选项带回主窗口。

## 方案选择

评估过三种布局方向：默认最大化可以提供最多结果行，但会强占整个桌面；保留 1240×820 固定布局只压缩间距，无法满足小窗口要求；最终采用 960×680 默认窗口与响应式网格。它在常规使用时保持轻量，最大化后又能自然增加结果行数，符合本项目作为桌面小工具的定位。

## 主窗口布局

顶部品牌区缩短高度，仅保留图标、名称、简短说明和帮助入口。扫描范围与重命名规则继续并列，但减少内边距和重复说明：左侧保留目录与层级，右侧把“查找”和“替换”放在同一网格行，两者各占可伸缩列。窗口变宽时输入框同步扩展；960 像素宽度下仍不换行。

操作区保留扫描、确认执行、匹配统计和预览上限，并压缩为单行。结果卡片成为主窗口唯一的纵向伸缩区域，默认可见行数由 5 行提高到至少 10 行，窗口放大后自动显示更多行。底部进度和状态区域减少固定宽度，避免制造空白。

窗口默认尺寸为 960×680，最小尺寸同样以完整可操作为准。所有关键区域使用 `grid` 权重参与尺寸分配，不通过固定像素预留空白。最大化与手动缩放均不需要特殊模式切换。

## 结果表与悬浮内容

结果表保留类型、原名称、新名称、所在目录、状态和说明。列宽按信息价值重新分配，状态与类型保持紧凑，名称和目录共享剩余宽度。横向滚动条不再永久占据一行；仅当内容确实超出可视宽度时才显示，恢复可容纳状态后自动隐藏。

鼠标移动到任意结果单元格时，程序识别当前行和列。只有内容被列宽截短时才显示悬浮卡片，卡片标题说明字段类别，正文显示完整内容；移出单元格、滚动或点击后立即收起。普通控件提示沿用相同的深色标题、浅色正文、圆润留白和屏幕边界修正，使提示不会跑出屏幕。

## 控件视觉系统

继续使用 Tkinter/ttk 和现有深蓝、青绿色品牌色，不引入额外 GUI 框架。输入框、数值框、按钮、复选框、单选框、进度条和滚动条使用专用样式名，统一边框、内边距、禁用态、悬停态和焦点态。

按钮区分主操作、次操作和轻量入口；输入与数值控件使用浅色底、清晰焦点边框；选择类控件增加足够点击区域；进度条使用低对比轨道与品牌色进度；滚动条采用窄轨道和圆润感较强的滑块配色。受 ttk 原生绘制能力限制，不模拟网页控件，但保证 Windows 高 DPI 下清晰一致。

## 正则模板库

模板数据增加分类和简短标签，示例窗口左侧按“日期时间、编号整理、文本清理、片段调整、扩展名”组织，右侧展示用途、查找表达式、替换内容、处理前和处理后。每条模板都通过真实 `RenameRule` 自动化验证。

首批模板覆盖：日期连接与日期分隔统一、文件序号补位、保留数字替换前缀、删除圆括号或方括号标签、去除首尾空白、合并连续空格、统一多个连接符、删除固定前后缀、交换名称片段、提取编号到开头，以及扩展名大小写整理。涉及扩展名的模板一键应用时会同步打开“包含扩展名”，其他模板保持扩展名保护。

模板入口在主窗口保持明显但不过度抢占空间。一键应用只填写规则和选项，不扫描也不修改磁盘；状态栏明确提示使用者先根据实际名称核对，再执行扫描预览。

## 状态、错误与安全

本轮不改变扫描、冲突检查和执行安全模型。无效正则或无效替换引用仍在主窗口即时提示。模板定义若不能产生文档所写的结果，自动化测试直接失败，避免把错误示例交给使用者。

悬浮提示不改变选择状态，不拦截表格双击和滚动。动态滚动条只影响可见性，不改变表格的滚动位置或结果数据。

## 验证

自动化测试覆盖 960×680 默认尺寸、最小布局请求尺寸、查找与替换同一行、结果表可见行数、横向滚动条自动显示逻辑、单元格完整内容解析、控件专用样式，以及每一条正则模板的一键应用选项。

完成后在 Windows 上分别以 960×680 和最大化状态实际启动，检查输入区不换行、列表扩展、悬浮内容、控件状态和滚动条行为。最后运行完整测试、字节码检查和 PyInstaller 单文件构建，并记录产物校验值。
