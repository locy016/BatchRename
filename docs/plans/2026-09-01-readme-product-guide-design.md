# README 产品介绍与操作视觉设计

## 目标

将 README 从功能清单提升为面向实际使用者的产品说明页，使首次访问 GitHub 的读者能够迅速理解软件用途、两阶段安全流程、界面结构、正则模板、安全边界和当前开发状态。

## 信息结构

README 按使用者的阅读顺序组织：

1. 品牌标题、产品定位、版本与发布状态；
2. 最新主界面真实预览；
3. 六步操作流程示意图；
4. 两阶段扫描与预览的职责说明；
5. 正则模板浮动面板真实预览；
6. 常用场景、核心能力与匹配统计解释；
7. 完整使用步骤、菜单与设置说明；
8. 正则模板示例、安全策略与扩展名保护；
9. 快速开发期路线、源码运行、测试构建和项目结构。

README 只介绍当前产品和已经实现的功能。设计取舍、问题根因、截图生成方式和验证过程统一写入 CHANGELOG。

## 视觉资产

### 主界面截图

继续使用真实 960×680 应用窗口，以测试目录构造安全预览，不执行任何重命名。截图需要完整展示顶部菜单、左侧六步工作流入口、四项统计、结果表、进度条和左下角工具入口。

### 正则模板截图

新增真实的正则模板浮动面板截图，展示分类、模板列表、只读表达式、替换内容、处理前后示例和“一键应用此规则”按钮。截图同样不执行扫描或磁盘修改。

### 流程操作示意图

使用仓库内 SVG 绘制六步流程，沿用深蓝、青绿色、浅灰和状态绿色：

`选择目录 → 查找规则 → 扫描匹配 → 填写替换 → 结果预览 → 确认执行`

每一步包含简短动作和安全提示，特别强调扫描只找名称、预览不重读目录、确认后才写入磁盘。SVG 不依赖外部服务，可在 GitHub README 中直接显示，并可随产品流程继续维护。

## 文案原则

- 使用自然中文介绍能力，不罗列“本次修改了什么”；
- 明确扫描、预览和执行的边界，避免把扫描与预览写成同一动作；
- 明确名称未变化仍属于匹配结果，避免查询语义误解；
- 撤回管理与操作日志只标注为开发中；
- 关于、菜单、浮动工具和快捷键使用与程序完全一致的名称；
- 重要目录备份、冲突阻止和使用者最终确认保持醒目但不过度重复。

## 验证与发布

验证 SVG 可解析、README 引用的本地图片均存在，检索旧界面和过时按钮名称，运行完整测试、字节码编译和 Git 差异检查。中文提交记录文档内容、视觉资产来源和验证结论，最后将当前功能分支推送至 GitHub；不重写远程历史。
